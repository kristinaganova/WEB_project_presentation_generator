Presentation Generator

Разпределена система за създаване, редактиране и експортиране на презентации

Какво решава?

Уеб приложение за управление на workspaces, презентации и слайдове с готови шаблони и real-time синхронизация между потребители.

Комуникационни парадигми

  • REST (HTTP/JSON) — външен достъп до ресурси
  • Микросервиз (PHP ↔ Node.js) — PDF генерация
  • WebSocket — collaboration в реално време
  • AJAX (Fetch) — динамичен UI без презареждане

Ключови функции

  • Workspaces + роли (owner/viewer)
  • CRUD за презентации/слайдове
  • Шаблони: текст, списък, цитат, 2 колони
  • Експорт: HTML / XML / PDF (микросервиз)

Бързи линкове (локално)

App: http://localhost:8000
Swagger: /api-docs.html
PDF service: http://localhost:3001/health
WS health: http://localhost:3003/health

Архитектура (overview)

Компоненти

Основното приложение е PHP MVC, което говори с MySQL, извиква PDF микросервиз по REST и синхронизира промени към клиенти през WebSocket.

Портове: PHP 8000 · PDF 3001 · WS 3002 · WS health 3003

Използвани технологии

Backend (PHP)

  • PHP MVC (controllers/models/views)
  • PDO (prepared statements)
  • Sessions + Auth middleware
  • TCPDF (алтернативен PDF път)

Node.js услуги

  • Express (PDF service)
  • Puppeteer (рендериране към PDF)
  • ws (WebSocket server)
  • CORS + health endpoints

Frontend/Docs

  • HTML/CSS/JS + Fetch API
  • Real-time client (auto reconnect)
  • Swagger UI + OpenAPI 3.0
  • Автоматизирани тестове

REST API (примерни endpoints)

Основни операции

  • GET /api/health — health check
  • GET /api/workspaces — списък
  • GET /api/presentations — списък
  • GET /api/presentations/{id} — презентация + слайдове
  • POST /api/presentations — създаване
  • POST /api/slides, PUT /api/slides/{id}, DELETE /api/slides/{id}

Аутентикация

UI е session-based (PHPSESSID cookie). За API се използва Bearer token със стойност PHPSESSID (след login).

Swagger: http://localhost:8000/api-docs.html
Test console: /api-test.html

PDF микросервиз (Node.js + Puppeteer)

Идея

PHP генерира HTML за презентацията и го изпраща към Node.js услуга по REST. Услугата рендерира HTML с headless Chrome и връща PDF (base64 → бинарно в PHP).

Endpoints

  • GET /health — статус
  • POST /generate-pdf — единичен PDF
  • POST /generate-pdf-batch — batch

Health: http://localhost:3001/health

WebSocket collaboration

Как работи

  • Room per presentation (по ID)
  • Broadcast към всички клиенти в room-а
  • HTTP endpoint /broadcast за нотификации от PHP
  • Client: auto-reconnect + status indicator

Здраве/връзка

WebSocket URL: ws://localhost:3002
Health: http://localhost:3003/health

Демо: отвори една и съща презентация в 2 прозореца → редактирай слайд → виж update в реално време.

Сигурност и качество

Security

  • Passwords: password_hash() / password_verify()
  • Authorization: access checks по workspace
  • PDO prepared statements (SQLi защита)
  • XSS: htmlspecialchars() във view-ове

Наблюдаемост

  • Подробни server logs (PHP)
  • Health endpoints за услугите
  • Ясни HTTP статуси/грешки в API

Тестове

  • PDF service: basic + extended тестове
  • PHP integration тестове
  • Swagger “Try it out” за API проверки

Резултати

Покрити изисквания

  • REST API (CRUD) + Swagger/OpenAPI
  • Микросервиз: HTML → PDF (Node.js)
  • WebSocket real-time collaboration
  • Документация + тестове

Качество

Фокус върху error handling, логване, ясни интерфейси между услугите и възможност за лесно демо/защита.

Какво демонстрираме на защита

1) Swagger UI: изпълнение на GET /api/presentations
2) PDF export: бутон “Експорт PDF” → генериран PDF (Node.js)
3) WebSocket: 2 прозореца → промяна → real-time update

Допълнително: health checks на трите услуги (8000/3001/3003).

Кратко демо (5 мин.)

Сценарий

  • Отвори /auth/login и влез
  • Dashboard → отвори workspace
  • Отвори презентация → “Преглед”
  • Експорт PDF (микросервиз)
  • Отвори същата презентация в 2 прозореца → редакция → real-time update

Силни talking points

- 3 независими услуги, 3 парадигми комуникация
- PHP ↔ Node.js интеграция (REST) + headless Chrome
- WebSocket room model + broadcasting + reconnection
- Документация + интерактивен Swagger + тестове

Ако нещо падне: покажи /api/health, 3001/health, 3003/health.
